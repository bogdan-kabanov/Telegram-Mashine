# Техническое задание: генератор отзывов (Bot AI)

Документ собран из согласований от 11.07.2026. Описывает продуктовую цель, бизнес-логику сценария, правила контента и поэтапную реализацию.

---

## 1. Цель продукта

Автоматизированная система, которая:

1. Настраивает двух AI-ботов (роли **клиент** и **менеджер / актриса**), взаимодействующих по заданным сценариям.
2. Генерирует истории, кейсы и отзывы в разных стилях.
3. Строит **многоэтапные** сценарии публикаций: история развивается постепенно, а не одним сообщением.
4. Генерирует текст, изображения и другие форматы контента.
5. Автоматически делает скриншоты переписки и публикует материалы в Telegram-группу / канал.

---

## 2. Продуктовая идея (простыми словами)

Есть переписка между двумя аккаунтами:

| Роль | Кто |
|------|-----|
| Клиент | Пишет менеджеру, хочет заработать; сначала не доверяет, жалуется на жизнь, задаёт вопросы |
| Менеджер (актриса) | Снимает сомнения, присылает гарантии и условия работы, ведёт клиента по этапам, поддерживает |

Ход истории:

1. Клиент пишет, рассказывает проблему / историю, задаёт вопросы.
2. Актриса отвечает, **обязательно** отправляет условия работы (картинка / GIF / текст — зависит от проекта).
3. Клиент готов приступить или ищет деньги.
4. Актриса присылает заготовленное сообщение с реквизитами (**свои на каждый проект**).
5. Клиент переводит деньги, скидывает чек; актриса подтверждает поступление.
6. Через время (**от ~30 минут**) актриса присылает первую ставку → клиент радуется → ещё две ставки с паузами между ними.
7. Актриса присылает заготовку: работа закончена, депозит и заработок.
8. Актриса просит номер счёта → клиент скидывает → актриса переводит деньги и присылает чек → клиент радуется.

Кружки и ставки загружаются заранее. **Чеки генерирует бот.**

---

## 3. Схема публикации в группу

### 3.1. Двухфазная публикация

| Фаза | Когда | Что публикуется |
|------|--------|-----------------|
| **Фаза 1** | Сразу | Первые **4** скриншота: клиент начал работу и внёс депозит |
| **Фаза 2** | Через **~1.5–2 часа** | Полный отзыв: все скрины (включая первые 4) + медиа |

### 3.2. Требования к «живому» отзыву

В полном отзыве **обязательно** должно быть хотя бы одно из:

- фотография;
- кружок (video note);
- видео.

Без этого отзыв выглядит как сухой скрипт («привет, хочу заработать → на деньги → ты заработал») — **так делать нельзя**.

## 4. Бизнес-правила и ограничения

### 4.1. Коэффициенты и суммы

- Фиксированного коэффициента нет.
- Есть **15–20 паков ставок**, используемых в отзывах:
  - 15 сумм депозита;
  - под них 15 сумм прибыли.

### 4.2. Двухчастные отзывы

- Две части отзыва — только на проекте **Нанси**.
- Задержка между частями: **1.5 часа**.

### 4.3. Номера лидов и банки

- В номерах лидов всегда видны **последние 4 цифры**.
- Цифры **всегда уникальны**.
- Банки, на которые отправляется прибыль клиентам, **меняются**.

### 4.4. Кружки и расписание

- Кружки готовые.
- Есть готовый **трёхнедельный цикл** и расписание под него.
- В расписании — большие и маленькие отзывы.
- Каждую неделю отдаётся **1 уникальный круг**, который затем **закрепляется** в канале.

### 4.5. Медиа

| Тип | Источник |
|-----|----------|
| Кружки (MP4) | Готовая библиотека |
| Ставки (изображения) | Готовая библиотека |
| Чеки | Генерация ботом по образцу (суммы, даты, время, банки, последние 4 цифры счёта) |
| Условия работы | Картинка / GIF / текст — по проекту |
| Реквизиты | Заготовки на каждый проект |

## 5. Функциональные модули (архитектура)

| Модуль | Назначение |
|--------|------------|
| Генератор диалогов | Сценарии, легенды, динамические подстановки, хронология |
| Медиа-обработчик | Кружки, ставки, чеки, пакет отзыва |
| Рендер / скриншоты | Реалистичные скрины чата |
| Планировщик | Расписание (~15 постов/сутки, интервал ~1.5 ч) |
| Публикатор | Публикация в Telegram, двухфазные посты |
| Управление | Команды / админка: старт, стоп, статус, отчёты |

Хранилище: JSON / файлы / БД для сценариев, скриптов, медиа, логов, конфигов (гео, банки, валюты, суммы, расписание).

## 6. Этапы реализации

> Пример разбиения. Этапы можно уточнять, но принцип «сдача по этапам» сохраняется.

### Этап 1 — Архитектура и инфраструктура

- Модульная структура: генератор диалогов, медиа, планировщик, публикатор.
- Хранилище: сценарии, скрипты, медиа-библиотеки, логи.
- Конфиги: гео, банки, валюты, диапазоны сумм, расписание.
- Базовое управление (Telegram-команды и/или админка): запуск / остановка / статус.

**Результат:** каркас читает настройки и выполняет базовые команды.

### Этап 2 — Генератор диалогов (без AI)

- Парсинг скриптов менеджера (по этапам) и легенд клиента.
- Случайный выбор легенды, подбор фраз менеджера.
- Подстановка динамики: имена, суммы, даты, банки, CLABE и т.п.
- Хронологическая цепочка сообщений (от контакта до благодарности) с задержками между этапами.
- Исключение повторяющихся комбинаций за заданный период.

**Результат:** уникальные диалоги как список сообщений с ролями, временем и метаданными.

### Этап 3 — Реалистичные скриншоты чата

- Headless Chromium / автоматизация UI чата.
- Ввод сообщений (эмодзи, форматирование), ожидание элементов, прокрутка, скриншот.
- Обработка ошибок (сбои, перезапуск браузера).
- Сохранение скринов с уникальными именами на отзыв.

**Результат:** скриншоты чата создаются автоматически.

### Этап 4 — Чеки и медиапакет

- Генератор изображений чеков по образцу.
- Случайный выбор кружков и ставок из библиотеки.
- Пакет отзыва: скрины + чек + кружок + ставка — в нужном порядке и с метками времени.

**Результат:** готовый пост со всеми медиа.

### Этап 5 — Планировщик и публикация

- Расписание: ~**15** публикаций в сутки, интервал ~**1.5** часа.
- Двухфазная публикация (см. §3.1).
- Логи: время запуска, ошибки, использованные переменные.
- Управление: `/pause`, `/resume`, `/status`; отчёты в личный чат.

**Результат:** автономная работа 24/7 без ручного вмешательства.

### Этап 6 — Тестирование и передача

- Прогон на тестовых данных: уникальность, корректность скринов и чеков.
- Исправление ошибок, оптимизация производительности.
- Передача исходного кода и финальный запуск / помощь в деплое.

---

## 7. Порядок работы с заказчиком

| Правило | Описание |
|---------|----------|
| Сдача по этапам | После каждого этапа — публикация изменений и доступ к тесту **по ссылке** |
| Код до оплаты | Исходный код у исполнителя; у заказчика **нет** доступа к репозиторию до полной оплаты |
| Оплата | После завершения всех этапов — крипта (предпочтительно) или карта |
| Выдача кода | Только после полной оплаты |
| Не работаем | Предоплата и гарант-схемы — **не используются** |

Руководство заказчика требует отчёт по каждому шагу; модель «этап → демо по ссылке → следующий этап» закрывает и контроль, и безопасность исполнителя.

---

## 8. Критерии приёмки (кратко)

- [ ] Диалог клиент ↔ менеджер проходит полный сценарий с паузами и поддержкой.
- [ ] Условия работы и реквизиты подставляются по проекту.
- [ ] Чеки генерируются ботом; кружки/ставки берутся из библиотеки.
- [ ] Фаза 1: 4 скрина (депозит); фаза 2: полный отзыв через ~1.5–2 ч.
- [ ] В полном отзыве есть фото / кружок / видео.
- [ ] Уникальность последних 4 цифр лида; смена банков; паки сумм 15/20.
- [ ] Для Нанси — двухчастный отзыв с задержкой 1.5 ч.
- [ ] Расписание ~15 постов/сутки; еженедельный уникальный круг с закрепом.
- [ ] Логи и команды управления работают; система крутится автономно.

## 9. Глоссарий

| Термин | Значение |
|--------|----------|
| Актриса | Роль менеджера в переписке |
| Кружок | Video note (круглое видео в Telegram) |
| Пак ставок | Связка сумма депозита ↔ сумма прибыли |
| Двухфазная публикация | Сначала тизер (4 скрина), потом полный отзыв |
| Легенда | Предыстория / стиль речи клиента |
| CLABE | Банковский идентификатор счёта (контекст гео/банков) |
